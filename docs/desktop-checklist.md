# Claude Desktop 確認表（版を出すたびに手で行う）

Claude Desktop のチャットは自動の試験ができないので、版を出すたびにこの表の依頼を、それぞれ新しいチャットで1回ずつ試す。

## 前提
- 拡張機能 coheads.mcpb（資料フォルダは空＝デモデータ、名前は「鈴木」）を入れてある。
- プラグイン coheads-plugin.zip を「カスタマイズ → プラグイン → 追加 → プラグインをアップロード」で入れてある。
- Gmail・Microsoft 365 など、普段使っているコネクタはそのまま有効にしておく（本物の競合がある状態で試す）。
- 拡張機能のツールの権限は「常に許可」にしておく（毎回の承認で止まらないように）。

## 記録
- 日付、拡張機能とプラグインの版、結果を、この表の下に追記する。
- 呼ばれなかったときは、AIが代わりに使った道具（Gmail、過去のチャットなど）も書く。

### 2026-11-26 12:28（拡張機能 0.3.2、プラグイン 0.3.1、チーム用のClaudeのプロジェクトの中、資料フォルダは空＝デモ）
- 1：○ Coheadsを呼んだ（あわせて過去のチャットも検索）。担当者名からA社と特定。月額120,000円（税別）。10万円は「11/24で失効」と説明。導入時期は日付を書かず「稼働日程が決まり次第調整」。提案書v1を渡しているかで2通りの文面を用意。文面にも説明にも「Coheads」の名前は出なかった（画面の「「Coheads」を使用しました」の表示はClaudeの画面側のもの）。
- 2〜5：未実施。

### 参考：プロジェクトの外（同日）
- 拡張機能だけ（0.1.0、0.2.1）では、同じ依頼でCoheadsは呼ばれず、Gmail・Microsoft 365・過去のチャットを探して空欄の雛形になった。Coheadsの名前を出して頼むと呼ばれた。

### 2026-11-26 16:30前後（拡張機能 0.3.4、チーム用のClaudeのプロジェクトの中、資料フォルダ coheads-try：架空のA社の資料5件、決定の記録なしから開始）
資料どうしの食い違い（SC-17、SC-18）と、#5に相当する確認。
- 食い違い（0.3.3）：金額を確定せず、10万円・12万円のどちらで書くかを選択肢で聞いた。説明に「決定台帳」と書いた（0.3.4で修正）。
- 食い違い（0.3.4）：「台帳」「Coheads」は出なかった。金額は聞かずに12万円で書き、根拠（11/24の価格承認記録、承認者：佐藤）と、正式な記録がまだないことを伝え、記録するかを聞いた。
- 「記録して」→ 候補を記録（16:31）、承認ページで承認（16:32）。新しいチャットで同じ依頼 → 「現在のチームの決定」として12万円で書いた。ただし「11/24に承認」と書いた（実際は11/26承認、11/24から有効）。→ 0.3.5で、現行の決定の行に承認日を出すようにした。
- 過去のチャットとの切り分け：同じプロジェクトの過去のチャットに12万円が残っているため、12万円の結果だけでは取得元が分からない。そこで、どのチャットにも出していない月額13万円の候補を、チャットを通さずに共有フォルダへ書き込み（ターミナル）、承認ページで承認した。新しいチャットで「A社に送る見積のメールを書いて」→ ○ 月額130,000円（税別）、「11/26に承認された現行価格」と書き、12万円は「11/26で失効」、10万円は提案書v1の旧い金額と説明した。13万円はCoheadsからしか得られないので、取得元はCoheads。過去のチャットにある12万円より、Coheadsの現行の決定が優先された。
