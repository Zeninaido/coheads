# L3：Claude Desktop での確認（版を出す前の最終確認）

Claude Desktop のチャットは自動の試験（L2）で動かせない。ここでは、L2 では確かめられないことだけを、条件をそろえて手で確かめる。

- 確かめること：Desktop のチャットで Coheads が呼ばれるか。画面とAIの文面に何が出るか（仕組みの名前が出ないか）。承認ページが使えるか。
- 確かめないこと：AIの判断の細かい良し悪し。それは L2（`eval/behavior`）で回数をそろえて見る。
- 結果の扱い：1回ずつなので、ここでの結果だけで仕様を決めない。気になる動きが出たら、L2 のケースに足して回数で確かめる。

## 条件（毎回そろえる）

1. **版ごとに新しい確認用プロジェクトを作る。** 名前は「Coheads 確認 0.x.y」。プロジェクトの指示には `docs/setup/project-instructions.md` の文をそのまま入れる。
   - 新しいプロジェクトには過去のチャットもメモリもないので、前の確認の答えが混ざらない。
   - プロジェクトのメモリの設定は「このプロジェクトだけ」（分けておく）にする。
2. **資料フォルダは評価用のものを複製して使う**（L2 と同じ資料）。下のコマンドで作り、拡張機能の「資料フォルダ」に `~/project/coheads-l3` を選ぶ。
3. 拡張機能とプラグインは、確認する版を入れる。普段使っているコネクタ（Gmail など）は有効のままにする（本物の競合がある状態で試す）。
4. 1項目ごとに新しいチャットを開く（項目2・3は同じチャットで続ける）。

```bash
rm -rf ~/project/coheads-l3
cp -R ~/project/coheads/eval/behavior/fixtures/a-sha-docs ~/project/coheads-l3
ls ~/project/coheads-l3
```

項目4のコマンド（チャットを通さずに候補を書き込む）：

```bash
D=~/project/coheads-l3/.coheads/events
mkdir -p $D
AT=$(date -u +%Y-%m-%dT%H:%M:%S.000Z)
ID=$(uuidgen | tr A-Z a-z)
cat > "$D/$(echo $AT | tr ':.' '--')-${ID:0:8}.json" <<JSON
{"v":1,"type":"proposed","at":"$AT","by":"佐藤","decisionId":"$ID","projectId":"A社","topicKey":"proposal.price","label":"提案価格","value":{"type":"money","amount":130000,"currency":"JPY","period":"monthly","tax":"excluded"},"validFrom":"$(date +%Y-%m-%d)","sources":[]}
JSON
```

取得元をはっきりさせたいときは、Desktop のチャットでツールを使った箇所を開き、Coheads の返答を見る。
