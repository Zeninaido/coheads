# 開発チャットからの回答（2026-11-26）

## 1. ※を付けた3つの問いと、v0のツール構成

### 失効の付け方
- 決定済みで、実装とテストも済んでいること
  - 「現行」は、状態ではなく有効期間で判定する。
  - 新しい決定が承認されると、同じ論点の旧決定は自動で失効する。理由は「置き換え」で、失効日は新しい決定の適用日になる。
- 未決で、未実装のこと
  - 置き換える決定がないまま失効させる操作（例：期間限定価格の終了）。仕様の型には「期限切れ（expired）」があるが、操作は作っていない。
  - 「保留（on_hold）」も、型にあるだけで未実装。

### AIに先に呼ばせるか
- 実装済み：サーバーの説明で、「メールやドライブを探す前に get_context を呼ぶ」ようAIに依頼している。依頼であって、強制ではない。
- 未決：ツールの説明文に案件名を載せるか（試験では、呼ぶべき依頼で差が出なかった）。
- 未実装：フック（ハーネス）で、Context Packを依頼文に必ず差し込む方式。仕様では任意の出力として位置づけている。

### AIに決定を提案させるか
- 決定済み：AIは propose_decision で候補を出せる。承認と却下は人（approver）だけ。承認を人の判断として残すため。
- 未検証：AIが実際に候補を出すか、出すべき場面で出すか。どの場面で出させるか（AIが自分から出すか、頼まれたときだけか）は未決。

### v0のツール構成
- 仕様書のv0：get_context と propose_decision の2つ。
- 試作：get_document を追加して3つ。資料をファイルの場所で渡すと、AIが自分で開こうとして失敗したため。
- 仕様書のインターフェースv0タブへの反映はまだ。v0はM3で凍結するまで変更できる。

  - 最初の18回：サーバーが起動しなかったため無効。
  - 1回ずつの接続確認が2回：1回は失敗、1回は成功。

## 6. 読者が自動試験を回せるか
- 回せる。必要なものは4つ。
  - リポジトリ一式。
  - Bun。
  - Claude Code（ログイン済み）。
  - コマンド2行：`bun run admin reset` と `bun run trials --n 3`。
- 対応しているのはClaude Codeだけ。ChatGPTなど他のAIでは回せない。
- 試験はClaude Codeの設定を一時的に別に作って動かすので、読者の普段の設定には影響しない。
- 所要時間：1条件18回で約4分（試験結果ファイルの時刻から）。
- 費用：まだ測っていない。
  - Claudeの定額プランで動かすと、プランの利用枠（チャットと共通）を使う。
  - APIキーで動かすと、従量課金になる。
  - 1回あたりの費用は、試験の記録に加える予定（Claude Codeが返す費用の値を保存する）。
