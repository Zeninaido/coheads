# 第1話の素材（開発チャットより、2026-11-26）

使ったモデル：Claude Opus 5.5（claude-opus-5-5、Claude Codeの既定のモデル）。2026-11-26 5時半の確認用の試験で記録した。それより前の試験はモデルを記録していないが、Claude Codeの設定は変えていないので、同じモデルと推定している。

データはすべて架空（A社・B社・田中様・佐藤・鈴木は架空の会社と人物）。AIの回答はClaude（Claude Code経由）が実際に出力したもの。整形は一切していない。

## 4. 「古い資料のままAIが書いた例」について

### 比較1：AIに資料フォルダを丸ごと読ませた場合（2026-11-26、Claude Code、各依頼3回、計12回）
- 条件：Coheadsをつながず、架空の資料7件（A社5件、B社2件）が入ったフォルダを、AIが自由に読める状態にした。「社内の資料はこのフォルダにある」とだけ伝えた。
- 結果：**12回すべてで、AIは正しい価格（月額12万円・税別）を使い、旧価格の10万円を現行として書かなかった。** 導入時期も、全回で未確定として扱った。
- AIは毎回、資料をほぼ全部（4〜5件）開いて読んでいた。資料の中に「価格承認記録」という、承認をはっきり書いた文書があったため、正しく判断できた。
- 小さな誤りが1回あった。「11月18日の定例メモでは月額10万円のまま」と書いたが、実際のメモには12万円に上げたいという意見が書かれている。
- 費用（Claude Codeの報告値、API料金に換算）：1回あたり平均0.07ドル。
- 読み方：資料が7件で、承認がきちんと文書になっていれば、AIは全部読んで正しく判断できる。「AIは古い資料に引っかかる」とは言えない。記事でもこの結果をそのまま書く。

### 比較2：台帳なしの資料検索（よくあるRAG）の場合（11/26、4依頼×3回、計12回）

- 結果：

## 4-2. 無効になった試験の経緯（第5話の材料）
- いつ：2026-11-26 5時ごろ（日本時間）。普通の検索との比較（比較2）の1回目。結果ファイルは eval/trials/2026-11-25T20-03-20-baseline-rag.json（ファイル名の時刻は世界標準時）。
- 何をしたかったか：台帳も注釈もない普通の検索をAIに使わせ、Coheadsとの差を見る。そのために、Coheadsのサーバーに比較用の設定（SB_PLAIN_SEARCH=1）を足した。この設定では、検索のツールは上位3件の抜粋だけを返す。
- 何が混ざったか：資料の本文を取るツール（get_document）を、比較用の設定でもそのまま使っていた。このツールは、本文と一緒に「■ 注釈（決定台帳との照合）」として「この文書の提案価格100,000円は現行ではない。現行は月額120,000円（税別）、11/24から適用（11/24承認）」を返す。ツールの説明文にも「決定台帳と照合した注釈を返す」と書いてあった。
- 結果：12回すべてでAIは正しい価格を使った。
- どう気づいたか：回答を1件ずつ読んでいて、「田中さんに送る見積」の回答に「決定台帳では月額120,000円（税別）に改定されています」とあった。比較用の検索は台帳を返さないはずなので、おかしいと気づいた。get_document の作りを読み直し、注釈が付いたまま返っていることを確かめた。
- どう直したか：
  - 比較用の設定では、get_document が本文だけを返すようにした。説明文からも「決定台帳」という言葉を外した。
  - 試験の記録に、AIが検索に使った言葉と、開いた資料を残すようにした。これで、AIが何を見て答えたかを後から確かめられる。
  - 直した版で流し直した（同日5時15分ごろ、eval/trials/2026-11-25T20-16-43-baseline-rag.json）。これが比較2の有効な結果。
- 教訓：比べる相手から、比べたい仕組みを完全に外せているかを、回答の中身で確かめる。数だけを見ていたら気づかなかった。
