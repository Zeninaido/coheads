# Coheads（コヘッズ）

[English](README.en.md)

> **開発中です。** M3 で正式に公開する予定です。それまで仕様は変わります。**まだ業務には使わないでください。** 試すときは、デモのデータか、試しのための資料を使ってください。

チームの「いま有効な決定」を、AI に渡す仕組み。

AI に見積のメールを頼むと、古い提案書やメールに残っている価格で書いてしまうことがある。Coheads は、チームで承認された決定を、承認日と有効期間つきで記録しておき、AI が取引先あての文面を書く前に渡す。資料に残っている古い値には「現行ではない」と注釈を付ける。決定の記録がまだないチームでも、資料どうしの金額の食い違いを知らせる。

- 対象：Claude Desktop（チャット、Cowork）と Claude Code。ChatGPT などは今後。
- 入れ方：Claude Desktop の拡張機能を1つ入れて、資料フォルダと名前を選ぶだけ。ターミナルは要らない。
- データ：利用者のパソコンの中だけに保存する。チームで使うときは、共有フォルダ（Google Drive など）の中に決定の記録を置く。
- 開発：WalkOn（株式会社銭内堂）。ライセンスは Apache-2.0。

## いまできること

- **AI が書く前に、チームの決定を確かめる。** 見積やメールを頼むと、AI はチームで承認された価格などを先に確かめ、それで書きます。古い値や、まだ決まっていない事項（納期など）は、決まったこととして書きません。
- **資料フォルダを読む。** Word、PDF、テキストの資料を読みます。資料どうしで金額が食い違っていれば知らせます。
- **決定は人が承認する。** AI は「候補」を出すだけです。このパソコンの中で開く承認ページで、人が承認・却下します。
- **承認ページでできること。** 承認する人の指定、ほかの AI（ChatGPT など）に貼る文面のコピー、最近 AI に渡したものの確認、やめ方とこのパソコンのデータの消去。
- **チームで試す。** 全員が同じ共有フォルダを選ぶと、誰かが承認した決定が、ほかのメンバーの AI にも届きます。

確かめているのは Mac です。Windows ではまだ確かめていません。

### 既知の点

- 資料どうしで金額が食い違い、どの資料にも承認した人の名前がないとき、AI は本来、文面を書く前に「どの金額で進めるか」を聞きます。試験では6回中1回、聞かずにいちばん新しい資料の金額で下書きを書きました（まだ決まっていないことと、確認のお願いは添えていました）。直す作業を進めています（[#29](../../issues/29)）。

## 次にやること

1. **Windows で動くことを確かめる**（[#7](../../issues/7)）。会社のパソコンの多くは Windows のため。
2. **新しい版を届ける方法を決める**（[#1](../../issues/1)）。いまは、新しい版が出ても自動では入れ替わりません。
3. **ChatGPT のデスクトップアプリから使えるか確かめる**（[#21](../../issues/21)）。Claude 以外の AI からも、同じチームの決定を使えるようにするため。
4. **資料から決定の候補を作る**（[#11](../../issues/11)）。新しい資料の金額が、承認された値と食い違ったときに、承認する人へ候補として出します。「案」「検討」と書かれたものは、まだ決まっていない事項として扱います。

## 試す

1. [リリース](../../releases) から `coheads.mcpb` を取り、ダブルクリックして「インストール」を押す。
2. 設定で「資料フォルダ」を選ぶ。中のフォルダが1つずつ案件になる（例：`A社/`、`B社/`）。空のままにすると、架空のデモデータで試せる。
3. チームで使うときは、Claude のプロジェクトを1つ作り、[プロジェクトの指示](docs/setup/project-instructions.md)を入れる。そのプロジェクトの中のチャットが、チームの決定とつながる場所になる。
4. Cowork や Claude Code でも使うときは、プラグイン `coheads-plugin.zip` も入れる。

決定の候補は、AI との会話の中で出せる。承認は、このパソコンの中だけで開く承認ページ（http://127.0.0.1:4319/）で人が行う。

## 開発

前提と原則は [CLAUDE.md](CLAUDE.md)、手順は [docs/development.md](docs/development.md)。

```bash
cd core && bun install
bun run test            # 自動テスト
bun run build           # dist/ に拡張機能とプラグインを作る
bun run eval --dry      # 挙動の評価のファイル検査（費用なし）
```
